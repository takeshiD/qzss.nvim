# Additional review cases

These observations were made by the coordinating agent while round 1 was still being implemented. They are review inputs, not acceptance decisions. The contractor and independent inspector should reproduce them against the final implementation and record the resolution in their normal evidence.

1. **Quoted YAML key identity:** parsing `"two  spaces": 1` currently produces a symbol named `"two spaces"`. Preserve whitespace inside quoted keys; two distinct YAML keys must not acquire the same displayed identity. Also check TypeScript literal types such as `type Spacing = "a  b" | "a b"`, and JSON string previews. Flattening formatting whitespace must not silently rewrite literal content.
2. **LSP character offsets:** the initial `backends/lsp.lua` converter copies `selectionRange.start.character` directly to a Neovim byte column. In an LSP-only outline, UTF-16/UTF-32 offsets after non-ASCII text need conversion using the responding client's encoding and the source buffer. Test an actual jump with a non-ASCII prefix on the same line; ASCII-only fixtures cannot establish exact column correctness. Confirmed with the real TypeScript language server and `backends = { 'lsp' }`: for `const text = 'あ😀'; function target<T>(x: T): T { return x; }`, jumping to `target` landed at byte column 29 instead of the correct zero-based byte column 33. The coordinating agent's reproduction is `.research/unicode-jump.lua` (ignored development scratch; add a portable regression to the deliverable).
